发表于 2026-10-26

前言

本文主要整理模型训练过程中，除模型本身以外的一些实用技巧。

姑且将 AI 系列后续内容分为以下 4 个部分：

  1. 学术篇： LLM 基础知识、模型训练、各类算法的原理与实现等。
  2. 开发篇： Agent 框架、各类 AI 应用的开发等。
  3. 运维篇： Agent 应用的部署、推理参数测试等。
  4. 杂项： AI 渗透、视频生成、音频生成、超分辨率等其他内容。

目前已经基本跑通了整个训练流程，但测试结果、Loss 展示等内容还需要进一步完善。这里先记录训练过程中用到的一些工具和操作，方便后续复现与参考。

主要包括：租用训练服务器、Windows WSL 安装、文件压缩与解压、文件上传与下载、硬件利用情况监测，以及使用 tmux 创建训练会话。

1. 租服务器

我的电脑毕竟只是一台笔记本，要用它跑模型训练还是有些勉强。因此，租用服务器就成了一个比较实际的选择（土豪除外）。

服务器租用平台有很多，例如阿里云等厂商也提供相关服务。不过，我对这方面接触不多，这次使用的是 AutoDL 算力云。

它的一个优点是支持按小时计费，很适合我这种只需要训练十几个小时的场景，不必为了偶尔的训练任务长期租用服务器。

AutoDL 算力市场：https://www.autodl.com/market/list

点击图中的「算力市场」，即可查看当前可租用的服务器。

在算力市场中，可以看到不同 GPU 型号对应的配置和价格。具体需要什么显卡，可以参考我前面介绍的两篇文章：模型训练加速和模型精度。

从下图可以看到，两个价格为 1.66 元/小时的实例已经被租完了。一般来说，这类价格便宜、配置又合适的实例比较抢手，能不能租到还得看运气。

选择一个仍可租用的实例，点击进入创建页面。

在创建页面中，根据自己的需求配置 GPU、镜像等选项即可。如果不清楚该如何选择，可以先使用平台提供的较新镜像，后续再根据实际需要调整。

其他软件也可以在通过 SSH 连接服务器后，自行使用 pip 或 apt 安装。

创建完成后，就可以在控制台的「容器实例」页面中看到刚刚创建的实例。

注意：模型训练完成，或者暂时不需要使用服务器时，一定要记得关机！

在「容器实例」页面中，点击对应实例右侧的「关机」按钮，即可停止实例运行，避免继续产生运行费用。具体计费规则以平台说明为准。

此外，实例还自带了 JupyterLab 工具。点击进入后，就可以直接在浏览器中查看和编辑已经上传到服务器的文件，不必每次都通过 SSH 操作。

2. windows上WSL安装

有时候，我们需要使用一些只能在 Linux 环境下运行的工具。如果平时主要在 Windows 上工作，每次为了使用这些工具切换系统就比较麻烦。

微软提供的 WSL（Windows Subsystem for Linux） 可以解决这个问题。通过 WSL，我们可以在 Windows 中安装和运行 Linux 发行版，例如 Ubuntu，而不必单独安装一套 Linux 系统。

最好的一点是，WSL 中的 Linux 可以直接访问 Windows 本地磁盘。 例如，Windows 的 F:\code\python 在 WSL 中对应 /mnt/f/code/python，我们可以直接读取、修改和运行其中的文件，修改后的文件在 Windows 中也能直接访问，无需像使用 VMware 那样额外配置共享文件夹来传输文件。

3.文件压缩与解压

一般来说，我们会先在本地准备好训练代码和数据集，再上传到服务器进行训练。

数据集往往比较大。我这次训练的一个小模型，相关文件加起来就有 1.8GB。直接上传不仅耗时，而且服务器通常按小时计费，上传时间越长，成本也越高。

因此，可以先在本地压缩文件，上传到服务器后再解压。这样能够显著减小上传的数据量，节省时间和费用。

这里使用的都是 Linux 下的命令行工具，因此推荐在 WSL 的 Ubuntu 中执行。

其中，GPU 利用率、显存占用率和功耗占比是训练时最值得关注的三个 GPU 指标。结合训练速度和 Loss 的变化，可以进一步判断是否需要优化训练流程。

6. tmux 创建训练会话

我们不可能一直开着 CMD，通过 SSH 连接服务器并保持窗口不关闭来运行训练。万一终端意外断开，就可能影响训练任务的正常运行。

因此，我们需要一种能够让训练任务在终端断开后继续运行，并且随时可以重新连接查看实时输出的方法。这里推荐使用 tmux。

它的主要优点是：终端断开后，训练程序仍然可以继续运行；重新连接时，还能看到之前的终端内容和实时输出，就像 CMD 窗口一直没有断开一样。
